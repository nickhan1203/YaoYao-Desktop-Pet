# 幺幺桌宠任务开发 Skill

## 何时使用
任何功能、Bug 修复、重构、素材处理、测试、跨平台适配或打包任务。

## 开始前必读
- `CODEBUDDY.md`
- `docs/PRD.md`
- `docs/ARCHITECTURE.md`
- `docs/CROSS_PLATFORM_WORKFLOW.md`
- `docs/TEST_PLAN.md`
- 相关 `.codebuddy/rules/` 与实际源码

## 流程

### 1. 明确任务边界
先写出目标、非目标、验收标准、预计修改文件、风险、依赖与平台影响。大任务拆成可独立测试的小任务。

### 2. 检查现状
阅读实际文件、Git 状态、package scripts、测试和依赖版本。不得只依据计划文档猜测项目结构。工作区存在未提交变更时，先说明，不覆盖用户改动。

### 3. 制定最小计划
说明要改什么、不改什么、如何测试。新增依赖或更改安全/打包设置时，先解释必要性。

### 4. 实施
- 保持 main / preload / renderer 职责分离。
- 保留 Electron 安全基线与窄化 IPC。
- 将纯逻辑做成可测试模块。
- 平台特有行为使用显式适配层，避免散落条件判断。
- 为新增逻辑补充测试；素材缺失时应优雅降级。

### 5. 自动化验证
仅运行项目实际存在的命令。常见候选包括单元测试、类型检查、lint 和生产构建。记录命令及真实结果，不伪造通过结果。

### 6. 平台验收
- 若当前在 Mac：完成 macOS 相关测试，输出 Windows 待验收清单。
- 若当前在 Windows：完成 Windows 相关测试，确认对应 Git commit SHA，并输出 macOS 待验收清单。
- 不能远程访问/运行另一端时，不得声称另一端已通过。
- 对窗口、托盘、点击/拖动、多显示器、安装/卸载分别记录实测结果。

### 7. 审查 diff
检查无关改动、不安全 IPC、资源路径、ticker/事件监听器清理、平台分支、测试覆盖和意外依赖升级。

### 8. 交付报告
返回：任务与 commit SHA、变更文件、实现概要、执行命令和结果、macOS 实测结果、Windows 实测结果、未验证项、已知问题、回滚方式、下一步。

## 停止并询问用户的情况
新增云服务/LLM/数据库/遥测/付费服务；上传幺幺照片；默认开启开机启动；降低 Electron 安全设置；大幅更换框架；删除原始素材或用户数据；执行发布或远程写操作。
